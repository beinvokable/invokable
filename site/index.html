01 · The problem

Every team shipping “a tool an agent runs” rewrites the same four layers.

Invokable is that layer, as a library. You write your commands and your API. The output format, login, the approval gate, and the agent instructions come from the packages.

Invokable gives developers the missing layers that let agents log in, understand outputs, install skills, and request human approval when actions have cost or risk.

  1. 01
    Installing instructions into the agent

    Hand-written prompts per agent → one generated SKILL.md, installed everywhere.

  2. 02
    Machine auth

    Pasting API keys into config → device-code login the agent can run itself.

  3. 03
    An output format the agent can parse

    Scraping human-formatted text → exactly one JSON document, plus a semantic exit code.

  4. 04
    A gate before it spends money

    Hoping the model asks first → a server-signed checkpoint a person approves once.

02 · Core product pillars

Agent-ready products are clear, structured, and actionable.

Browser-based login

Every tool gets login, logout, whoami and doctor without writing them. Device-code flow, token stored 0600, written atomically.

Structured JSON output

One document on stdout, enforced not requested. Semantic exit codes and a remediation on every error, so the agent never has to guess the next command.

Self-installing skills

init turns your schema into a portable SKILL.md and installs it for Claude, Codex, Cursor, Gemini and any Agent Skills host. Byte-identical everywhere.

Signed checkpoints

Stop a command before it spends money. The fingerprint is issued by the server, bound to the plan, expires in 24h and is consumed exactly once. Replays fail.

03 · How the pieces fit

The agent, your CLI, your server.

A thin contract between three parties. Add a command to the CLI and it shows up in the skill and on the MCP surface with no extra code.

The agent

Claude · Codex · Cursor · Gemini

  • Reads the generated SKILL.md
  • Runs your CLI with --json
  • Decides what to do next from the exit code alone
Your CLI

@invokable/core

  • One JSON document, one exit code
  • Built-in login, whoami, doctor, init
  • checkpoint() before anything that spends
Your server

@invokable/server

  • Device-flow auth endpoints, OAuth 2.1 for remote MCP
  • Issues and verifies checkpoints, exactly once
  • Your API, guarded where it spends money

Hosted auth when you want it, self-hosted when you need it. The SDK renders the price and compares it to --max-spend. Your server decides what a credit is worth.

04 · The contract

Define the surface once. The runtime guarantees what the agent sees.

Structured. Typed. Agent-ready.

  • Exactly one JSON document on stdout. While a command runs, stray writes are diverted to stderr so a dependency cannot corrupt the document.
  • Semantic exit codes. 0 ok, 3 auth, 5 not found, 10 checkpoint pending. Tools may add codes in 30–99.
  • Remediation on every error. The literal next command to run.

2
3const tool = defineTool({
4  name: 'deployer',
5  version: '0.1.0',
6  commands: {

8      description: 'Deploy a service to an environment.',
9      options: { env: { type: 'string', required: true } },
10      run: async ({ opts, ctx }) => {
11        ctx.io.note('planning…');   // → stderr, always
12        return { env: opts.env, replicas: 3 };
13      },
14    }),
15  },
16});
17
18await cli(tool);

05 · Human approval

Human approval for actions that cost money.

A checkpoint is a third status: not an error, not a success. The agent gets exit 10 and a pre-rendered panel, so every agent shows the user the same thing instead of paraphrasing what they are about to pay for.

Over MCP, status: "checkpoint" becomes an elicitation. The person approves the spend, not the model.

06 · Check the contract holds

Works on any CLI, not just one built with the SDK.

The contract is the interface. Run invokable-test against an existing binary and see exactly where it stops being agent-usable.

$ npx invokable-test node bin/my-tool.mjs
  • --version --json returns a valid ok envelope
  • --help --json returns a command manifest
  • An unknown command exits 2 with an error envelope
  • A bare invocation does not exit 0
  • doctor --json reports auth and config state
  • Every exit code is reserved or in 30–99
  • --json puts exactly one JSON document on stdout
  • No credential-shaped strings on stdout
  • Errors carry a remediation
  • 9 passed

08 · FAQ

Questions, answered directly.

What is Invokable?

Invokable is an open source SDK that makes an API or CLI usable by AI agents. It provides the four layers every agent tool needs: browser-based login, one structured JSON document with semantic exit codes, self-installing agent instructions (SKILL.md), and server-signed approval checkpoints for actions that cost money or carry risk.

Which AI agents does Invokable work with?

Invokable generates a portable SKILL.md and installs it for Claude Code, Codex, Cursor, Gemini and any agent that follows the Agent Skills standard. It also updates AGENTS.md, CLAUDE.md, Copilot instructions and Cursor rules. For hosts that cannot run a shell, the same tool can be exposed over the Model Context Protocol (MCP).

How does Invokable stop an agent from spending money without approval?

A checkpoint returns a third status, exit code 10, with a server-issued fingerprint bound to the gate, subject and plan summary. A person approves it, the approval is consumed exactly once by the action it authorises, and a replay or a plan that changed underneath is refused with checkpoint_stale.

Is Invokable open source?

Yes. The core, server, skills and conformance packages are MIT licensed and published on npm. You can self-host the auth server or use the hosted auth service.

Do I have to rebuild my CLI to use Invokable?

No. You define your commands once with @invokable/core and get login, logout, whoami, doctor, structured output and checkpoints for free. The conformance checker also works on any existing CLI, not only ones built with the SDK.

Who is Invokable for?

Developer tools teams, SaaS products, platform builders, and companies preparing their products for agent-native usage.
